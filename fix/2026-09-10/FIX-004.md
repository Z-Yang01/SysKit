- **补丁**：mediaflow/FIX-004.patch

## 位置
- `backend/app/api/v1/module_ai/rag/chunker.py:137`（`_split_text` 游标推进）

## 现象
PROGRESS.md 记录：test_ai_rag_unit.py 全文件执行时 python RSS 膨胀至 7.4GB 被 OOM kill，
WSL 当晚崩溃 4 次。最小复现（size=100, overlap=20）：

```python
TextChunker(100, 20)._split_text("x"*19 + "\n" + "y"*3000)
# 修复前：无限 append 直至 MemoryError（1.5GB 内存上限下复现，chunker.py:134）
# 修复后：57 个 chunk，瞬时返回
```

## 根因
`start = end - self.chunk_overlap`：end 由「窗口内最后分隔符+分隔符长」决定，当分隔符紧邻
start（距 start 不足 overlap）时 `end - overlap <= start`，游标停滞（上例 `\n`@19 →
end=20 → start=20-20=**回到 0**）甚至倒退为负（负索引又令 rfind 从文本尾部搜索）→
`while start < len(text)` 永不结束 → chunk 列表无限增长。

## 修改
`start = max(end - self.chunk_overlap, start + 1)`——保证每轮严格前进 ≥1 字符；
正常场景（分隔符距 start 超 overlap）语义不变，病态场景无丢字、必然终止。

## 验证
- 复现脚本：MemoryError → **57 chunks / exit 0**
- `pytest tests/test_ai_rag_unit.py -k chunker` → 4 passed + 1 xpassed（原 ..FX + 会话级 MemoryError）
- 全文件（此前执行即 OOM）→ **18 passed in 7.4s**；移除理由失效的 paragraph xfail 标记

低（病态输入由死循环变为 1 字符步进扫描，输出多而有限）。回滚：`git revert 9dd63bc`。
